Core Components Architecture

HealthChecker
Responsible for performing health checks on all system components
  • performFullHealthCheck() Executes checks on all components
  • checkNetworkConnectivity() Tests external network access
  • checkValidationService() Validates service availability
  • checkDatabaseConnectivity() Tests database connections
  • getOverallHealth() Calculates system health status
AlertService
Multi-channel notification system for failure alerts
  • sendAlert() Main alert dispatch method
  • _sendSlackAlert() Formats and sends Slack notifications
  • _sendEmailAlert() Handles email notifications
  • _sendWebhookAlert() Posts to webhook endpoints
  • _executeAlert() Routes alerts by channel type
RecoveryService
Intelligent auto-recovery system with configurable strategies
  • attemptRecovery() Orchestrates recovery attempts
  • _recoverNetwork() DNS cache flush and network recovery
  • _recoverValidationService() Service restart and API recovery
  • _recoverDatabase() Connection refresh and DB recovery
  • _executeRecoveryAction() Executes recovery with retry logic
PublishingPipelineMonitor
Main orchestrator coordinating health checks, alerts, and recovery
  • start() Initializes monitoring loop
  • performHealthCheck() Executes health checks and handles failures
  • handlePipelineFailure() Processes component failures
  • attemptRecovery() Triggers recovery operations
  • getDashboardStats() Calculates monitoring statistics

// Health Check Execution Flow
async performHealthCheck() {
    // 1. Execute all component checks in parallel
    const results = await Promise.allSettled([
        this.healthChecker.checkNetworkConnectivity(),
        this.healthChecker.checkValidationService(),
        this.healthChecker.checkDatabaseConnectivity()
    ]);

    // 2. Analyze results and update metrics
    const healthyResults = results.filter(r => r.status === 'fulfilled' && r.value.isHealthy);
    const failedResults = results.filter(r => r.status === 'rejected' || !r.value.isHealthy);

    // 3. Update statistics
    this.totalChecks++;
    this.successfulChecks += healthyResults.length;
    this.failedChecks += failedResults.length;

    // 4. Handle failures
    for (const failure of failedResults) {
        await this.handlePipelineFailure(failure.value || failure.reason);
    }

    // 5. Log system status
    AuditLogger.logSystemStatus(
        healthyResults.length === results.length,
        results.length,
        failedResults.length,
        { checkId: uuidv4() }
    );
}

Monitoring Algorithms & Calculations

Key Metrics Calculations

Uptime Percentage Calculation

uptimePercentage = (healthyChecks / totalChecks) × 100

Calculated from the last 100 health checks stored in the uptimeHistory array. This rolling average provides a current view of system stability.

Success Rate Algorithm

successRate = (successfulChecks ÷ totalChecks) × 100

Tracks the percentage of health checks that pass successfully across all components since the monitor started.

Recovery Rate Calculation

recoveryRate = (successfulRecoveries ÷ totalRecoveryAttempts) × 100

Measures the effectiveness of the auto-recovery system by tracking successful recovery operations.

Retry Strategy Implementation

function calculateRetryDelay(attempt, strategy) {
    switch (strategy) {
        case 'FIXED':
            return baseDelay;
        case 'EXPONENTIAL':
            return baseDelay * Math.pow(2, attempt - 1);
        case 'LINEAR':
            return baseDelay * attempt;
    }
}

Configurable retry strategies prevent overwhelming failing services while ensuring recovery attempts.

Error Handling & Recovery Strategies

Error Classification & Handling

// Error Handling Strategy
class ErrorHandler {
    static classifyError(error) {
        // Network errors
        if (error.code === 'ECONNREFUSED' || error.code === 'ENOTFOUND') {
            return { type: 'NETWORK_ERROR', recoverable: true, priority: 'HIGH' };
        }

        // Timeout errors
        if (error.code === 'ETIMEDOUT' || error.message.includes('timeout')) {
            return { type: 'TIMEOUT_ERROR', recoverable: true, priority: 'MEDIUM' };
        }

        // Authentication errors
        if (error.response?.status === 401 || error.response?.status === 403) {
            return { type: 'AUTH_ERROR', recoverable: false, priority: 'CRITICAL' };
        }

        // Default case
        return { type: 'UNKNOWN_ERROR', recoverable: false, priority: 'LOW' };
    }

    static getRecoveryStrategy(errorType) {
        const strategies = {
            'NETWORK_ERROR': ['dns-refresh', 'network-restart'],
            'TIMEOUT_ERROR': ['connection-refresh', 'service-restart'],
            'DATABASE_ERROR': ['connection-restart', 'pool-refresh']
        };

        return strategies[errorType] || ['manual-intervention'];
    }
}

Recovery Execution with Timeouts

// Recovery Action Execution with Timeout Protection
async _executeRecoveryAction(actionName, actionFn, options = {}) {
    const { maxAttempts = 3, timeout = this.config.recoveryTimeout } = options;

    for (let attempt = 1; attempt <= maxAttempts; attempt++) {
        try {
            // Execute action with timeout protection
            const result = await Promise.race([
                actionFn(),
                new Promise((_, reject) =>
                    setTimeout(() => reject(new Error(`${actionName} timed out`)), timeout)
                )
            ]);

            // Success - return result
            return { success: true, result, attempt };

        } catch (error) {
            // Log failure attempt
            this.logger.warn(`${actionName} failed (attempt ${attempt}/${maxAttempts})`, {
                error: error.message,
                attempt,
                maxAttempts
            });

            // Wait before retry (with exponential backoff)
            if (attempt < maxAttempts) {
                const delay = this._calculateRetryDelay(attempt, this.config.retryStrategy);
                await new Promise(resolve => setTimeout(resolve, delay));
            }
        }
    }

    // All attempts failed
    throw new Error(`${actionName} failed after ${maxAttempts} attempts`);
}

Performance & Scalability

Performance Characteristics

Concurrent Health Checks

The system uses Promise.allSettled() to execute all health checks concurrently, ensuring that a slow network check doesn't delay database or validation service checks. This parallel execution keeps the total monitoring cycle time minimal.

Memory Management

class PublishingPipelineMonitor {
    constructor() {
        // Circular buffers for memory efficiency
        this.uptimeHistory = new Array(100).fill(true); // Last 100 checks
        this.consecutiveFailures = new Map(); // Component failure tracking
        this.recoveryHistory = []; // Limited to last 10 recoveries

        // Automatic cleanup
        setInterval(() => {
            if (this.recoveryHistory.length > 10) {
                this.recoveryHistory = this.recoveryHistory.slice(-10);
            }
        }, 300000); // Clean every 5 minutes
    }
}

Memory usage is controlled through circular buffers and automatic cleanup of historical data.

Timeout Protection

All network operations include configurable timeouts to prevent hanging operations. The default 5-second timeout ensures the monitoring system remains responsive even when services are unreachable.
